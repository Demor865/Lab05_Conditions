## Пример кода

Фрагмент кода функции `GetHint()` из игры «Угадай число», использующий `switch`:

```csharp
static string GetHint(int diff)
{
    switch (diff)
    {
        case int n when n <= 3:
            return "🔥 Огонь! (Горячо)";
        case int n when n <= 10:
            return "🌡️ Тепло";
        default:
            return "❄️ Холодно";
    }
}
```

## Ответы на контрольные вопросы

**1. Чем `int.TryParse()` безопаснее `int.Parse()`? В каких случаях стоит использовать каждый?**
`int.Parse()` выбрасывает исключение (ошибку), если строку невозможно преобразовать в число (например, при вводе текста), что приводит к аварийному завершению программы. `int.TryParse()` в этом случае просто возвращает `false` и не ломает программу.
_Использование:_ `TryParse()` нужно использовать при обработке ввода от пользователя (где могут быть опечатки). `Parse()` — когда вы на 100% уверены в формате данных (например, при чтении из проверенного файла).

**2. Когда `switch` удобнее, чем цепочка `if/else if`? Приведите пример из реальной жизни.**
`switch` удобнее, когда мы сравниваем одну переменную с конкретными, заранее известными значениями (константами). Это делает код визуально чище и понятнее.
_Пример из жизни:_ Выбор пункта в меню банкомата или интерактивном голосовом меню по телефону («Нажмите 1 для проверки баланса, 2 для перевода...»).

**3. Что произойдёт в `switch`, если убрать `break` после одного из `case`?**
Произойдет «проваливание» (fall-through). Программа выполнит код этого `case`, а затем сразу перейдет к выполнению кода следующего `case` (даже если его условие не совпало), пока не встретит `break`.

**4. Чем отличается `=` от `==` в C#? Почему это частая ошибка?**
`=` — это оператор присваивания (мы кладем значение в переменную: `x = 5`). `==` — это оператор сравнения (мы проверяем, равны ли значения: `if (x == 5)`). Это частая ошибка, потому что в математике мы привыкли использовать один знак равенства для сравнения, а в программировании для этого нужен двойной.

**5. Можно ли написать тернарный оператор внутри другого тернарного оператора? Приведите пример из кода лабораторной и оцените читаемость такого кода.**
Да, можно, но это сильно ухудшает читаемость.
_Пример:_ `string result = score >= 91 ? "Отлично" : score >= 71 ? "Хорошо" : "Плохо";`
Код получается компактным, но если вложенность глубже двух уровней, его становится очень трудно читать и сопровождать. Лучше использовать обычный `if/else`.

## Итоговая таблица: что изучили в лабораторной

| Команда / элемент                | Что делает                                           |
| :------------------------------- | :--------------------------------------------------- |
| `if (условие) { ... }`           | Выполнить блок кода, если условие истинно            |
| `else { ... }`                   | Выполнить блок, если условие ложно                   |
| `else if (условие) { ... }`      | Проверить следующее условие, если предыдущее ложно   |
| `&&`                             | Логическое И — оба условия должны быть `true`        |
| `\|\|`                           | Логическое ИЛИ — хотя бы одно условие `true`         |
| `!`                              | Логическое НЕ — инвертирует значение условия         |
| `условие ? A : B`                | Тернарный оператор — вернуть A если `true`, иначе B  |
| `switch (x) { case ... }`        | Выбор ветки по конкретному значению переменной       |
| `break`                          | Выйти из блока `switch` (обязателен в каждом `case`) |
| `default:`                       | Ветка `switch` по умолчанию (аналог `else`)          |
| `Random random = new Random()`   | Создать генератор случайных чисел                    |
| `random.Next(1, 101)`            | Получить случайное число от 1 до 100 включительно    |
| `int.TryParse(str, out int val)` | Безопасно преобразовать строку в число               |
| `continue`                       | Перейти к следующей итерации цикла                   |
